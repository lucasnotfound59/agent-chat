# Agent Chat 第一期设计：中枢、网页界面、四个常驻联系人

日期：2026-11-11
状态：设计已逐段确认，待实施计划

## 1. 目标

做一个本机聊天应用，人和多个 agent 都是其中的成员，可以私聊和群聊。它的作用是打通 agent 之间的壁垒：不同 harness 里的 agent 能互相交流，同时各自原有的用法不受影响。

需要兼容的 agent：Claude Code、Codex、OpenCode、DeepSeek Harness（DSH）、DeepSeek QQ Companion（拾潮）。

## 2. 总体路线与本期范围

整个项目分五期，每期单独设计、单独实施。

| 期 | 内容 |
|---|---|
| 1（本文档） | 中枢、网页界面、四个常驻联系人：Claude Code、Codex、OpenCode、DSH |
| 2 | 活会话接入：用户在外面开着的 agent 会话通过 MCP 加入聊天 |
| 3 | 聊天里派活：在 agent 自己的 harness 里起独立任务会话，聊天里显示任务卡片 |
| 4 | 拾潮频道：同一份人设和记忆，聊天软件作为 QQ 之外的又一个频道 |
| 5 | 打包成 Mac 桌面 App |

本期不做：活会话接入、派活和任务卡片、拾潮、桌面打包、手机端、多用户、多台机器。

本期必须为后续留好的口子：
- 中枢只认"成员"和"消息"，不含任何 agent 的细节，第二、四期新增接入方式时不用改中枢核心。
- 界面是纯网页，中枢是独立进程，第五期的壳子只负责启动中枢并加载网页。
- 数据目录固定在 `~/Library/Application Support/AgentChat/`，打包前后位置不变。

## 3. 已确定的产品决定

- 成员形态：常驻联系人和活会话两种都要；本期只做常驻联系人。
- 软件本身是完整的聊天应用：私聊、群聊、@、回复、附件、历史记录；人和 agent 是平等成员。
- 群聊中 agent 自由发言，不限于被 @。
- 聊天只说话不干活；干活通过第三期的派活在外部 harness 执行。
- 先部署在用户这台 Mac 上，结构要能打包。

## 4. 架构

全部用 TypeScript，一个仓库三个包。

```
packages/
  hub/        本机后台服务：存储、接口、调度器
  adapters/   每个 agent 一个适配器，实现同一个接口
  web/        React 网页界面
```

### 4.1 中枢（hub）

- 管成员、会话、消息，存进一个 SQLite 文件。
- 对外两个接口：HTTP 用于查询和发消息，WebSocket 用于实时推送新消息、输入状态、成员在线状态。
- 只监听 127.0.0.1。启动时生成一个本地令牌，界面凭它连接。令牌存放在 macOS 钥匙串中，不写入数据目录（见第 6 节）。
- 包含调度器（见第 5 节）。
- 通过适配器接口唤起 agent，自身不含任何 harness 相关代码。

### 4.2 适配器（adapters）

统一接口，语义如下：

- `check()`：返回该 agent 是否可用；不可用时给出原因（没安装、没登录）。
- `invoke(请求)`：请求包含会话 ID、该 agent 在此会话的 harness 会话 ID（可为空）、自上次发言以来的新消息、附件的只读路径、中止信号。返回回复正文或"不开口"，以及本次使用的 harness 会话 ID。执行过程中可以上报"正在输入"。

每个适配器内部负责：起对应命令行子进程、续接会话、解析 JSON 事件流、收到中止信号时结束子进程。

| agent | 调用方式 | 续接会话 | 只读方式 |
|---|---|---|---|
| Claude Code | `claude -p`，JSON 输出 | 按会话 ID 续接 | 只放行读取和联网搜索类工具 |
| Codex | `codex exec` | `codex exec resume <id>` | `--sandbox read-only` |
| OpenCode | `opencode run --format json` | `--session <id>` | 工作目录内的 `opencode.json` 定义只读 agent `agentchat`（禁用命令执行和写入） |
| DSH | `dsh --profile headless --json` | `--session-id <id>` | `--approval-policy never` 加只读权限预设 |

各命令的确切参数在实施时以本机安装版本的 `--help` 为准（当前：Claude Code 2.1.322、codex-cli 0.167.0、opencode 2.2.6、DSH 0.2.2-rc.1）。

会话映射规则：每个 agent 在每个聊天会话里对应一个它自己的 harness 会话。群里的上下文和私聊的上下文互不串。

"不开口"的约定：适配器在提示里告诉 agent，如果没有要说的就只回复一个固定标记；适配器识别到该标记后返回"不开口"，中枢不产生消息。

另有一个假适配器，行为可由测试脚本设定，供所有自动测试使用。

### 4.3 界面（web）

- 左侧：联系人和群的列表，显示未读数和在线状态。
- 右侧：消息流，支持 Markdown、代码块、@ 成员、回复某条、发送文件和图片。
- 显示 agent 的"正在输入"。
- 群设置：成员、发言模式参数、暂停按钮。
- 顶部全局停止按钮。
- 设置页：点名模型的接口地址和密钥、各 agent 的自我介绍、各 agent 的可用状态。

### 4.4 一条消息的流动

1. 用户在某会话发言，界面通过 HTTP 提交。
2. 中枢落库，通过 WebSocket 推给界面。
3. 调度器决定唤起哪些 agent、按什么顺序。
4. 适配器跑子进程，期间上报"正在输入"。
5. 回复作为新消息落库并推送；它又成为调度器的新输入。

## 5. 调度器

输入：某会话来了新消息。输出：按顺序唤起一组 agent。

### 5.1 私聊

对方必回，不经过判断。

### 5.2 群聊

1. **合并等待**：最后一条消息之后安静 3 秒才开始一轮，期间的多条消息算一次。
2. **点名**：
   - 被 @ 的 agent 必定入选。
   - 其余的由一次小模型调用决定。输入是最近的消息和每个成员的自我介绍，输出是本轮该发言的成员及顺序，可以为空。
3. **依次发言**：入选的 agent 逐个唤起，后一个能看到前一个刚发的消息。被选中的 agent 可以返回"不开口"。

同一个会话同一时间只跑一轮；一轮进行中到达的新消息排到下一轮。

采用集中点名而不是每个 agent 自行判断的原因：自行判断等于每条消息都完整启动所有 harness，又慢又贵。代价是初筛不是 agent 本人做的，它只保留拒绝权。

### 5.3 限制

- 连续没有人类发言的轮数上限，默认 6。到顶后该群停止唤起，直到人类再次发言。
- 每个会话每日唤起次数上限，默认 200，私聊和群聊都适用。到顶后该会话里出现一条系统提示。
- 每群暂停按钮：暂停期间不唤起任何 agent，消息照常收发。
- 全局停止：暂停所有群，并中止所有正在跑的子进程。

以上数字都是每群可改的设置。

### 5.4 点名模型

- 配置为任意 OpenAI 兼容接口，用户在设置页填写地址、密钥、型号。
- 本节已由第二期设计（`2026-11-12-agent-chat-phase2-mcp-design.md` §4.4）取代：点名改为走已登录的 agent，整个软件不再使用任何 API 密钥。
- 未配置或调用失败时，该轮退化为只有被 @ 的 agent 发言。

## 6. 权限

原则：聊天只说话，不干活。

- 每个 agent 在聊天里使用数据目录下的专属空工作目录，不是用户的项目目录。
- 一律只读运行，具体方式见 4.2 的表格。
- 聊天时默认不加载用户在各 harness 里配置的 MCP 服务和插件，因为它们运行在 harness 的只读限制之外。设置里可以对单个 agent 打开；打开后该 agent 的只读取决于用户装了什么，中枢不再保证。
- 只读不等于隔离：agent 能读取磁盘上用户可读的文件，部分 agent 还能联网。因此访问令牌存放在 macOS 钥匙串，而不是 agent 读得到的文件里。
- agent 可以读本会话的附件、联网查资料、互相讨论，不能修改用户机器上的文件。

## 7. 数据

位置：`~/Library/Application Support/AgentChat/`

```
agentchat.db        SQLite
config.json         点名用哪个 agent、各 agent 的设置（不含任何密钥或令牌）
attachments/        附件，按会话分目录
workspaces/<agent>/ 各 agent 聊天用的空工作目录
```

表：

| 表 | 主要字段 |
|---|---|
| members | id、类型（人/agent）、名字、自我介绍、适配器名 |
| conversations | id、类型（私聊/群）、标题、设置（合并等待秒数、轮数上限、每日上限、是否暂停） |
| conversation_members | 会话 id、成员 id |
| messages | id、会话 id、发送者 id、类型（普通/系统）、正文、@ 列表、回复的消息 id、附件列表、创建时间 |
| agent_sessions | 会话 id、成员 id、harness 会话 ID |
| invocations | id、会话 id、成员 id、触发原因、起止时间、结果（已回复/不开口/超时/出错/中断） |

首次启动时自动创建一个人类成员和四个 agent 成员，以及人与每个 agent 的私聊。

## 8. 出错处理

| 情况 | 处理 |
|---|---|
| agent 超时（默认 5 分钟）或子进程崩溃 | 会话里插入一条系统消息，带重试按钮；记入 invocations |
| agent 没装或没登录 | `check()` 失败，联系人显示离线并写明原因；调度器跳过它 |
| harness 会话 ID 失效 | 开新会话，把最近 30 条聊天记录作为上下文补进去，更新映射 |
| 点名模型调用失败 | 该轮退化为只有被 @ 才回 |
| 中枢重启 | 启动时把未结束的 invocations 标记为中断，不自动重跑 |

## 9. 测试

- 调度器：假时钟、假点名模型、假适配器做单元测试，覆盖合并等待、点名、依次发言、轮数上限、每日上限、暂停、全局停止。
- 中枢接口：对临时数据库做集成测试。
- 适配器：每个真实适配器用录制的 JSON 事件流测解析和"不开口"识别。
- 界面：Playwright 配合假适配器跑端到端，覆盖发消息、@、群聊多 agent 依次回复、暂停。
- 真实 agent：每个一条手动冒烟脚本，会产生费用，不进自动测试。

## 10. 完成标准

- 在本机启动中枢和界面后，能与四个 agent 分别私聊，并在多轮之间保留上下文。
- 能建群拉入多个 agent；在已配置点名模型的前提下，不 @ 任何人发一个问题，相关的 agent 会自行回应，并能相互接话。
- 无人类发言时，agent 之间的连续对话在达到轮数上限后停下。
- 暂停和全局停止立即生效。
- 聊天中的 agent 无法修改工作目录以外的文件。
- 自动测试全部通过。
